# Getting help with Carrier

Start with the [README](README.md) and [documentation](docs/README.md), then search
[existing issues](https://github.com/Aixand/carrier/issues) for the same question or error.

We welcome issues. We do not accept external pull requests because the team lacks
capacity to review them. See the [participation policy](CONTRIBUTING.md).

Use the [issue forms](https://github.com/Aixand/carrier/issues/new/choose) for:

- **Usage questions:** setup, configuration, or how to use the project.
- **Bug reports:** reproducible behavior that differs from the documentation.
- **Documentation:** unclear instructions, missing examples, or broken links.
- **Feature requests:** the problem you want to solve and the expected benefit.

Include the version or source commit, operating system, relevant setup, what you
tried, and the smallest example that explains the issue. Redact credentials,
private file paths, personal information, and confidential data from logs or
screenshots. Public issues are visible to everyone.

Report vulnerabilities privately using [SECURITY.md](SECURITY.md). Report conduct
concerns using [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md). Send private licensing
concerns to [corporate@aixand.org](mailto:corporate@aixand.org).

Support is provided by community maintainers as availability permits. Opening an
issue does not create a response-time, resolution, or commercial support
commitment.

## Report code ownership or licensing concerns

If you believe Carrier includes material without permission to distribute it,
email [corporate@aixand.org](mailto:corporate@aixand.org) privately. Include:

- The affected files or code blocks and commit or version.
- The original work, its source, and evidence supporting your concern.
- The relevant ownership, license terms, or distribution restrictions.
- Your relationship to the rights holder and a way to contact you.

Share only material you are authorized to disclose. Describe confidential evidence
before sending it so maintainers can arrange an appropriate review method.
Do not post confidential source code in public issues.

Maintainers investigate credible reports and may request clarification. If evidence
establishes that we lack distribution rights, we remove or replace the material.
Other substantiated licensing problems require corrective action, such as fixing
attribution or notices. AI assistance does not excuse unauthorized use.
